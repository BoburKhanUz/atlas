### Re-review of the fixes (`73990a9...4c21c7b`)

A third fresh reviewer read the fix diff: all rows above confirmed, plus 1 blocking and 4
should-fix findings, all fixed with tests that fail on the code before:

- Missing tests for the throttle in item detail, outfit detail and outfit item images (blocking):
  added (an already-expired answer reloads once, not per report; a rejected URL backs off).
- A URL that keeps failing reloaded every 30 s while the screen was open: `RefreshThrottle` now
  backs off (doubling up to 10 min) and returns to 30 s once URLs last a whole interval.
- Outfit detail dropped an expiry reported during a save, rename or delete: reloaded when it ends.
- Uploads or deletions during the first load or a category switch were overwritten: kept.
- A later successful upload cleared the "may be stored" mark of an earlier cancelled one: tracked
  per upload key.

Notes kept as they are: a deferred URL reload can repeat a pull-to-refresh that just ran (one
extra request); leaving add-item after a cancel reloads the first page (`refresh`); while the
old URL's load is still running a fresh URL shares it (one extra throttled round); the weather
queue's "drains after a failed task" path is unreachable today (the tasks catch everything).

## Security gate (lookly-security, 2026-11-25)

M1 changed only `apps/mobile` and docs; no server, CI or dependency change. Areas touched:
uploads (add-item cancel), sessions (the server clock offset stored with the tokens), consent
(D7), signed media URLs (refresh and the `Image` key), error reporting.

- **Differential review** (by hand; the plugin is not loaded in this session):
  - No check was removed. D7 lets a restored session into the app before `/auth/me` answers. The
    server still refuses every request with `CONSENT_REQUIRED` until the texts are accepted, so
    no data is served without consent; the refusal turns the consent screen on.
  - The clock offset is not secret. It only decides when a URL looks expired. A wrong offset at
    worst causes extra reloads, now throttled and backed off.
  - Signed URLs still never reach logs or errors; the `Image` key is the URL's hash.
  - Cancel keeps the idempotency key and the recovery record, so a retry cannot create a duplicate.
- **Static analysis:** `flutter analyze` clean. semgrep is not installed here and has no useful
  Dart rules; CodeQL is planned before release.
- **Flutter storage and transport checklist:**
  - Tokens stay only in secure storage (unchanged), and the offset is stored in the same record.
  - New log lines carry error types and platform codes only, never messages, URLs or tokens
    (tested). Crash reports go through `ErrorScrub`.
  - Keychain reinstall handling, HTTPS-only builds and the logout wipe are unchanged.
  - The new in-memory state (throttles, kept edits, cancelled upload keys) is rebuilt per user or
    disposed with its screen.
- Not applicable: the server checklists (sessions, uploads, AI, quotas, cookies, admin) and
  secrets/CI. Nothing on the server or in CI changed.
