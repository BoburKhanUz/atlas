# B0 — Go backend skeleton

Started at `409d7aa` (2026-11-25). Stage goal and exit criteria: `docs/plan/README.md`.

## Problem

There is no Go service yet. Every later backend stage (B1–B8) needs the same base: a
binary that starts only with valid configuration, answers in the contract's error
envelope, logs safely, reports its health, builds in CI and ships as a container. Without
it each stage would invent these parts again, and the first real endpoint would also be
the first test of the foundations.

## Solution

`apps/api` holds a Go service, `lookly`, built from the OpenAPI contract. It serves
`GET /api/health` exactly as the contract and the current server do. It refuses to start
with missing or invalid configuration and says what is wrong. Every error leaves it in the
contract's envelope with a request id, and it shuts down cleanly. It is tested and
linted in CI and builds as a small container image. Nothing points at it yet: users keep
talking to the Next.js API until the cutover (B7).

## User stories

1. As the operator, I want the server to refuse to start when configuration is missing or
   invalid, with a message naming the variable, so that a broken deployment never serves
   traffic.
2. As the operator, I want `GET /api/health` to report the database state and the version,
   so that Docker and monitoring can tell a healthy instance from a degraded one.
3. As a client, I want every error, including unknown routes, malformed requests and
   crashes, in the documented envelope with a request id, so that error handling is the
   same for every endpoint.
4. As a client, I want my `X-Request-Id` (if well-formed) echoed, so that a support report
   can be matched to the server log.
5. As the operator, I want logs as JSON with request id, route, status and duration, and
   never secrets or bodies, so that logs are searchable and safe to share.
6. As the operator, I want a stop signal to let running requests finish (bounded), so that
   a deploy does not cut requests off.
7. As a developer, I want the server interface generated from the contract, with CI failing
   when it is stale, so that the Go server cannot drift from what clients expect.

## Decisions

- **Code generation:** the contract is used as is (OpenAPI 3.1, no preparation step) with
  oapi-codegen's strict net/http server, nullable fields as `Nullable` types. The
  generated interface contains only the operations implemented so far; each stage adds
  its operations. A test lists the remaining ones until B7 (ADR 0008). — default.
- **Validation in tests:** responses are checked against the contract with kin-openapi
  using its JSON Schema 2020-12 validator and an ECMAScript regex engine. The contract's
  email pattern needs lookahead, which Go's regexp lacks (ADR 0008). — default.
- **Configuration names:** variables shared with the Next.js server keep their names
  (`DATABASE_URL`). New Go-only variables use the `LOOKLY_` prefix. The environment
  (`LOOKLY_ENV`) is required and has no default, so a server never silently runs in
  development mode. — default (CLAUDE.md naming rule).
- **B0 validates only what B0 uses** (environment, listen address, database URL and pool,
  log level, shutdown grace). Each later stage adds its own settings to the same
  fail-closed check (JWT and session keys in B2, media secret in B4, AI and mail in B3 and
  B6). — default.
- **Unknown route or method:** 404 `NOT_FOUND` in the envelope. The contract has no
  method-not-allowed code, and the Next.js API also answered 404 for unknown paths.
  — default.
- **Version:** stamped at build time (`-ldflags`), `dev` otherwise. It appears in the
  health response and the startup log. — default.
- **Container:** a static binary on a distroless, non-root base image. A `lookly health`
  subcommand serves as the Docker health check, because the image has no shell or curl.
  — default.
- **Database in B0:** a pgx connection pool, used only to ping. No queries, no migrations
  (ADR 0007: Prisma owns the schema until B7). — default.

## Contract impact

None. `GET /api/health` is implemented as documented; no document change.

## Testing

- Seam: HTTP, through the real router and middleware, with responses validated against
  the contract. Configuration is tested as a pure function of the environment.
- Missing `LOOKLY_ENV`, unknown environment, missing or malformed `DATABASE_URL`, an
  invalid listen address, log level, pool size or grace period: each one refuses with
  the variable's name, and a value from the database URL is never printed.
- The binary exits non-zero with the message when configuration is invalid (no listener
  opened).
- Health: database up gives 200 `{status: ok, database: ok, version}`; database down or
  slow gives 503 `{status: degraded, database: unreachable, version}` within the ping
  timeout; `Cache-Control: no-store`; both are valid against the contract.
- Health against a real PostgreSQL 16 (integration build tag, run in CI).
- Error envelope: every contract code maps to the status the contract documents for it,
  and to the Uzbek message the Next.js server uses (parity with
  `apps/web/src/server/http.ts` until B7). Every envelope is valid against
  `ErrorResponse`.
- Unknown route, wrong method, malformed request (rejected by the generated decoder), a
  panic in a handler: each gives the envelope, no internals; a panic is logged with the
  request id.
- Request id: a valid `X-Request-Id` is echoed; a missing or invalid one is replaced by a
  generated one, on success and on error.
- Logs: one JSON line per request with request id, method, route, status and duration;
  query strings, headers and bodies are not logged.
- Graceful shutdown: a request in flight when the stop signal arrives completes; new
  connections are refused; the process exits within the grace period.
- Generated code is current: CI regenerates it and fails on a difference.

## Out of scope

- Every endpoint other than health, the data layer, migrations, River, auth, rate
  limiting and the body-size limits per route (B1–B8). The default JSON body limit is
  part of B0, because it applies to every route.
- `worker`, `migrate` and `eval` subcommands (added by the stages that need them).
- Deploying the Go service anywhere, or routing any traffic to it (B7).

| Exported `RequestID` unused | Removed |
| A second stop signal was ignored | It ends the process at once (exit 130); checked on the built binary |
| The aborted-request path skipped its access line; the probe client honoured proxy settings; the integration test's 50 ms ping was tight for CI's password auth | Fixed |

Kept as is, with the reason:
- The health warning logs the driver's error text. It names the database user and host,
  never a password. It is needed to diagnose an outage.
- `freeAddr` in the app tests closes a port before reuse: a small collision window.
  Configuration refuses port 0, and a collision fails loudly rather than passing.
- A typed-nil `*apierr.Error` would panic. Recovery turns that into a logged 500.

## Security gate (lookly-security, 2026-11-25)

B0 touched configuration, secrets handling and CI. It has no auth, uploads, AI or quotas.

- **Fail closed.** Every setting is validated at startup and an invalid one stops the
  process before it listens. There are no default secrets and no development fallback;
  in production debug logs are refused and the database `sslmode` must be explicit.
- **Secrets.**
  - `DATABASE_URL` never appears in an error, in `fmt` output, in a log line, or in a
    driver error passed on (all tested).
  - Every new log call was read: request lines carry the route pattern, status and
    timing (never the query, headers or body, tested); panics log their type and stack,
    not their value (tested).
  - Rule for later stages: the "internal error" line logs a service's error text, so
    services must not put personal data or secrets into error messages.
- **CI checklist.**
  - gitleaks, actionlint 1.7.7 and zizmor 1.14.2 are clean. The new job inherits
    `contents: read` and checks out without credentials.
  - It adds no third-party action: Go comes from the runner, the toolchain from `go.mod`,
    checksum-verified.
  - The tools are pinned (`staticcheck@v0.8.2`, `govulncheck@v1.9.0`, verified by the Go
    checksum database).
- **Dependencies.** govulncheck reports no vulnerabilities, after kin-openapi was raised
  from v0.142.0, which had nine. New modules: pgx (driver), oapi-codegen runtime and
  tool (ADR 0008), kin-openapi and regexp2 (tests only, not linked into the binary).
- **Container.** distroless static, non-root, no shell. The runtime image is pinned by
  digest; the build image is pinned by tag only (recorded for B7).
- **Not run here.** semgrep (not installed; CodeQL is planned before release). The full
  image build and the `api` job run in CI, because Docker Hub rate-limited the build image.
