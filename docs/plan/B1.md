# B1 — Data layer

Started at `f7a9826` (2026-11-25). Stage goal and exit criteria: `docs/plan/README.md`.
Binding decisions: ADR 0007 (Prisma owns the schema until B7), ADR 0001.

## Problem

The Go service can ping PostgreSQL but has no way to describe the schema, run typed
queries or do work in the background. Every later stage needs these.
- Endpoints (B2–B6) need typed SQL.
- AI analysis (B6) and image variants (B4) need a job queue.
- The cleanup that today is a manual script (`apps/web/scripts/session-cleanup.ts`, never
  scheduled) needs a home.

Without a recorded schema equal to Prisma's, the Go code would also drift from the
database it shares.

## Solution

- **Schema.** The Go service has a migration directory whose first migration is a
  baseline equal to the Prisma schema. A test fails whenever the two differ.
- **Queries.** They are written in SQL and turned into typed Go code by sqlc; CI fails
  when the generated code is stale.
- **Background work.** A `lookly worker` process runs background jobs from a River queue
  whose tables live in their own `river` schema, out of Prisma's way.
- **Cleanup.** Its first job removes what the manual script removes, plus expired
  idempotency keys and weather cache rows, once an hour.
- **Live system.** Nothing changes the shared database's schema. Nothing runs against
  production until the owner approves a deployment.

## User stories

1. As a developer, I want the Go schema to equal the Prisma schema, checked on every
   push, so that queries written in Go match the database the Next.js API uses.
2. As a developer, I want SQL queries to become typed Go functions, and CI to fail when
   generated code is stale, so that a column change breaks the build, not production.
3. As the operator, I want expired security records removed on a schedule, so that the
   database does not grow without bound and old tokens stop being stored:
   - successor ciphertexts older than 60 s;
   - rotated sessions and dead families after 30 days;
   - expired reset links.
4. As the operator, I want expired idempotency keys and weather cache rows removed too,
   so that those tables stay small.
5. As the operator, I want each cleanup run to log what it removed, as counts, so that I
   can see it working without reading the database.
6. As the operator, I want the worker to refuse to start, saying what to run, when
   River's tables are missing, and to stop cleanly on a signal (a running job finishes or
   is cancelled within the grace period).
7. As the operator, I want River's tables created by one explicit command, into their own
   schema, so that Prisma never sees them and production gets them only when I approve.

## Decisions

- **Migration tool: goose (v3).** Plain SQL files, embedded in the binary, run through
  pgx. The baseline is `00001_baseline.sql`: Up only, no Down (ADR 0007). Before B7 no
  command runs Go migrations against a shared database. Recording the baseline as
  applied, and taking over ownership, are part of the B7 cutover runbook. In B1 the
  migrations create test databases only. — default.
- **Baseline source.** It is produced from a PostgreSQL that has every Prisma migration
  applied (up to `20261017010000_password_reset`), with `pg_dump --schema-only`, then
  cleaned (no owners, no `_prisma_migrations`). It is never hand-edited. The equality
  test compares the two databases through the system catalogs:
  - tables and columns, with type, nullability and default;
  - constraints, indexes and their definitions;
  - functions and triggers.

  A Prisma migration added before B7 means rebuilding the baseline (it runs only in test
  databases until then), or the test fails.
  — default.
- **Queries: sqlc (v1.31.1)** over the migrations, pgx v5 driver, generated code
  committed. Timestamps are `timestamp(3)` without time zone, holding UTC (Prisma's
  choice), so they map to `time.Time` and every value passed in is UTC. — default.
- **Jobs: River (v0.51.2)** with its tables in the schema `river`. Prisma manages only
  `public`, so it neither shows them as drift nor proposes to drop them.
  `lookly migrate river` applies River's own migrations. `lookly worker` runs the queue.
  — default (ADR 0007).
- **Clock.** Cleanup compares against the database clock `atlas_now()`, like the Node
  script and the session protocol, so app servers and the database never disagree. Tests
  replace `atlas_now()` with a settable clock (the Node tests' technique). — default.
- **Retention**, the same rules as the manual script (`docs/architecture/sessions.md`,
  Operations):
  - successor ciphertexts: cleared 60 s after rotation;
  - families revoked, or past their absolute limit, for more than 30 days: deleted, with
    their sessions;
  - rotated sessions more than 30 days old, of other families: deleted;
  - reset links: deleted once expired.

  Added:
  - idempotency keys: deleted once expired (they are 24 h and already ignored then);
  - weather cache rows: deleted once expired (only ever overwritten after that).

  `AiUsage` (quota history) and `LegalConsent` (proof of consent) are never deleted by
  cleanup. — default; these match documented behaviour or remove only rows no code reads.
- **Schedule.** Hourly, and once at every worker start; at most 3 attempts per run. One
  read-committed transaction with `lock_timeout` 5 s. It locks the dead families first,
  in id order, as the session protocol does, and takes other session rows only when
  nobody holds them (`SKIP LOCKED`), so it cannot block or deadlock a sign-in. Runs are
  not serialised: concurrent cleanups are safe, and a job left "running" by a killed
  worker blocks nothing. — default.

## Contract impact

None.

## Testing

- Seam: the data layer against a real PostgreSQL 16 (integration tag). Each test uses a
  throwaway database created and dropped by the test helper. The worker is tested
  in-process through its command, as `serve` is.
- Schema equality: Prisma's migrations and the Go baseline, applied to two fresh
  databases, give identical catalogs. Any difference (column, type, default, index,
  constraint, function) fails with the object named. A test also proves that a changed
  schema is caught.
- Generated code: `scripts/generate.sh --check` covers sqlc as well as oapi-codegen.
- Cleanup, the scenario of the Node test `CLEANUP-01`, rebuilt with direct inserts:
  - live family rotated at day 0, 25 and 50;
  - families logged out at day 0 and 40;
  - run at day 61;
  - expected: 3 ciphertexts cleared, 2 rotated sessions deleted, 1 family with 1
    session deleted, 1 expired reset link deleted, live data untouched.

  Further cases:
  - the 60 s boundary;
  - the 30-day boundary;
  - idempotency and weather boundaries;
  - a second run deletes nothing;
  - a locked table makes the run give up within the lock timeout and change nothing.
- Worker:
  - refuses to start without River's tables (message names `lookly migrate river`);
  - runs cleanup at start;
  - logs the counts;
  - stops on a signal.
- `lookly migrate river`: creates the `river` schema and tables, is idempotent, and
  leaves `public` untouched (the schema-equality comparison still passes after it).

## Out of scope

## Stage review (lookly-code-review, 2026-11-25)

Two fresh reviewers read `f7a9826...7c1e5d6`:
- standards: 2 blocking, 4 should-fix, notes;
- spec and decisions: 0 blocking, 2 should-fix, notes.

The second reviewer rebuilt the baseline independently (byte-identical), confirmed that CI
enforces schema equality, and compared every cleanup predicate with the Node script. A
third reviewer then read the fixes (`7c1e5d6...faee41a`): 1 blocking, 2 should-fix,
notes. Every finding was checked against the code; confirmed ones got a test that fails
on the code before.

| Finding | Outcome |
|---|---|
| The cleanup locked a dead family's sessions before the family, the reverse of the session protocol: a refresh deadlocked with it (blocking) | Dead families are locked first, in id order; explicit read-committed transaction |
| The same on live families through the ciphertext step (found in the re-review) | Session rows of live families are taken with `SKIP LOCKED` |
| Three cleanup rules had no test: each SQL mutation survived (blocking) | Tests pin them; each mutation now fails |
| `generate.sh --check` passed when contract generation failed: `if ! generate` switched off stop-on-error (blocking, introduced by the first fixes) | Each step fails explicitly; checked with a broken generator config and a broken sqlc config |
| The start-up cleanup was skipped after a restart within the hour; later, a job left "running" by a killed worker blocked the next ones | Runs are not unique any more; concurrent cleanups are safe (tested with four at once) |
| River's default of 25 attempts | At most 3 attempts per run |
| A job still running after the grace period: untested | Tested: cancelled, exit 1 |
| An unreachable database read as "run migrate river" and printed the user, database and host | "cannot reach the database" with the reason class or SQLSTATE only (`database.Describe`) |
| Schema equality ignored data a migration inserts; the difference test covered three kinds of object | Row counts compared; constraint, function, trigger and data row covered |
| `make-baseline.sh`: non-atomic write, no pg_dump version check, loose filters | Atomic write, version check, data guard, exact filters; output byte-identical |
| The deadlock test relied on a 300 ms sleep | It waits until PostgreSQL shows the cleanup blocked, or finished |

Accepted, with the reason:
- River's own runtime error logs (database lost while running) can name the database
  user, name and host, never the password. Logs are for the operator; scrubbing a
  library's messages by pattern would be fragile.
- `lookly worker` has no liveness probe of its own (B7 deployment note in
  `docs/architecture/backend.md`).
- A job a killed worker left "running" is retried by River after its rescue interval
  (1 h by default). That is one harmless extra run.

## Security gate (lookly-security, 2026-11-25)

B1 touched the data layer, session rows (the cleanup), secrets handling in messages, and
CI scripts. No endpoint, auth decision or upload changed.

- **ADR 0007 holds.** No command applies Go schema migrations: only tests import
  `migrations.Apply`. River's tables live in the schema `river`; a test proves `public`
  is unchanged after `lookly migrate river`.
- **Data deletion.**
  - The cleanup removes only what the documented rules allow.
  - Every rule, and each boundary at the millisecond, has a test that fails when the
    rule is loosened.
  - Consent records and quota history are never deleted (tested).
  - It runs in one transaction with a lock timeout.
  - It runs only where a worker is deployed. In production that needs the owner's
    approval (CLAUDE.md rule 8).
- **Locking.** The cleanup follows the session protocol's order (family before session)
  and cannot deadlock with a refresh or a revocation (tested on dead and live families).
- **Secrets.** Operator messages never contain the database URL or its parts (tested for
  an unreachable server and for a server that refuses). The configuration's log value
  hides the URL. SQL is static; the only formatted value is the lock timeout, a number
  we format ourselves.
- **Dependencies.** goose v3.30.0, River v0.51.2 and sqlc v1.31.1 (a tool, not linked)
  are pinned; all are at least two weeks old. govulncheck reports no vulnerabilities.
- **CI.**
  - The `api` job enforces schema equality and fresh generated code, and the gate fails
    when generation itself fails.
  - The mobile job now caches Gradle and retries only on registry errors.
  - actionlint 1.7.7 and zizmor 1.14.2 are clean.
- **Not run here.** semgrep (not installed; CodeQL is planned before release).

## Notes for B2 (from the B1 review)

- Pass times to queries in UTC: pgx stores the wall clock of a non-UTC `time.Time` as is.
- A refresh can find its token's session deleted by a cleanup that committed in between
  (0 rows under `FOR UPDATE`): that is `INVALID_TOKEN`, not 500.
- A replay at the edge of the 60 s grace window can lose its ciphertext to a concurrent
  cleanup: it must fail closed (`SESSION_RACE`).
