# B6 — AI: providers, vision, stylist, colour profile, monitoring, evaluation

Stage of the Go backend (`docs/plan/README.md`). Started at `f1cded3` (2026-11-27).
Status: in progress.

## Problem

The Go server serves everything but the AI: garment analysis is the development mock
only, generated outfits are never ranked or explained by a model, and the stylist chat,
the colour profile, the client error reports and the contract's own document are still
answered by the Next.js API. Until these move, the Next.js API cannot be retired (B7).

## Solution

Port, behind the same contract and with the same prompts:

- the provider layer (Gemini and OpenAI over plain HTTPS, the mock; configuration that
  fails closed; timeouts, one retry, the error kinds);
- quotas, the rollout switch and the content-free monitoring events;
- the garment analysis of an upload with a real provider;
- the ranking and explanation of generated outfits;
- the stylist chat with its conversations;
- the colour profile (deterministic, in process, no provider);
- client error reports and `GET /api/v1/openapi.json`;
- an `eval` command, so that the offline evaluation runs against the Go pipeline.

No paid AI call is made in this stage: every test uses the mock or a scripted provider
answering over a stand-in HTTP server (owner rule 4). A live smoke of the two adapters
is an owner decision (below).

## User stories

1. As a user, I want my garment photo analysed (kind, colours, season, …) with honest
   confidences, and to be told when the photo is not a garment or is unusable.
2. As a user, I want the stylist to answer in Uzbek about my own wardrobe, naming my
   items, and my conversations kept.
3. As a user, I want generated outfits ranked and explained by the model when it is
   available, and the deterministic answer when it is not, never an error.
4. As a user, I want my colour profile worked out from a selfie that is not stored,
   shown again later, and deleted when I ask.
5. As a user, I am told when I have used the day's allowance (`AI_QUOTA_EXCEEDED`) or
   when the AI is not available (`AI_UNAVAILABLE`), and I am not charged for a failure.
6. As the operator, I choose the provider and model by configuration, switch a feature
   off, open it to a share of users, and the server refuses to start on a setting it
   does not understand or on a mock in production.
7. As the operator, I see what each AI call cost and how it ended, without any user
   content in the logs.
8. As the operator, I can run the offline evaluation against the Go pipeline, and a
   live one only with an explicit call and cost cap.

Unhappy paths, each with the contract's code: provider timeout, refusal, malformed or
invalid output (refund, `AI_UNAVAILABLE` 503 with `Retry-After`; for outfits the
deterministic answer); content filtered (`INVALID_IMAGE`, charged); not a garment
(`NOT_A_GARMENT`, charged); quota spent (`AI_QUOTA_EXCEEDED` 429 until the Tashkent
midnight; for outfits the deterministic answer); feature off or user outside the
rollout (mock analysis for uploads, `AI_UNAVAILABLE` for the chat, deterministic
outfits); idempotent replays and conflicts of the chat; a conversation that is not the
user's (`NOT_FOUND`); a selfie that cannot be analysed (`PHOTO_QUALITY_TOO_LOW`,
`SKIN_NOT_VISIBLE`, `INVALID_IMAGE`, `IMAGE_DIMENSIONS`).

## Decisions

Each is a default (decided here, not by the owner) unless marked.

- **In the request, not in jobs** (ADR 0011): the three operations that wait for a
  provider keep their synchronous contract in this stage.
- **Prompts byte for byte** (owner rule 6): the three prompts, their version constants
  and the JSON context the model is given are the TypeScript ones, held by golden
  vectors of the exact request body each adapter sends for a given input. No wording
  changes in this stage.
- **Provider layer.** What an adapter sends is the Next.js adapter's, byte for byte
  (the body), with these differences on purpose: a redirect is not followed (the key
  would follow it; the Next.js `fetch` followed redirects), an answer is read up to
  8 MiB, a `Retry-After` that is neither whole seconds nor a date is no value (what
  JavaScript's `Date.parse` makes of other text differs between engines), and a null
  part in a Gemini answer is a malformed answer (the Next.js adapter fell over it with
  a JavaScript error). With a schema, the text returned is the model's JSON made
  compact, not re-serialised by JavaScript: the same value.
- **Configuration** is the Next.js parser's, rule for rule (golden vectors of
  accepted and refused environments), with the Go server's stricter habits kept: an
  unknown value stops the server.
- **Image mathematics.** The colour analysis, the blur check and the colour cross-check
  work on small canvases. Their arithmetic is held to the TypeScript code by golden
  vectors that give Go the same canvas pixels. How a photo becomes a canvas differs
  (Go's decoder and resampling, ADR 0009, are not sharp's), so a photo at the very edge
  of a threshold can fall on the other side: accepted, and measured on the test photos.
- **Limits not in the Next.js API** (security checklist: expensive endpoints have
  per-user limits): the colour analysis is counted in the quota the Next.js code
  defines for it and never charged (`color_analysis`, 10 a day); client error reports
  are limited in PostgreSQL (the Next.js limiter is in process memory). Codes only the
  Go server answers are listed as `goOnlyErrors` in the contract's registry, as in B5.
- **Monitoring** keeps the event names and fields (`ai.call`, `ai.request`,
  `ai.quota`, schema version 2) and the whitelist every event passes (golden vectors),
  so the existing aggregation reads the Go server's logs. Each line carries `ts` (the
  time as the Next.js log lines wrote it, which the aggregation reads) beside the Go
  logger's own `time`. `environment` is `LOOKLY_ENV`, so `staging` is a value now; the
  Next.js server wrote `NODE_ENV`.
- **Quotas** count on the rows the Next.js server counts on (`AiUsage`), with its
  statement. On purpose: the day is taken from the database's clock in the statement
  itself (the Next.js server passed its own clock), a refund goes to the day that was
  charged (the Next.js refund named the day of the request's start, the same day
  unless the request crossed midnight in Tashkent), and a refund is made even when
  the client has left (the unit would be lost otherwise).
- **Evaluation.** The scoring and reporting of the evaluation harness stay where they
  are (TypeScript tooling under `apps/web/scripts/ai-eval`); the pipeline they score
  becomes the Go one, reached through `lookly eval`. The exact interface is decided in
  its slice, after the harness is read.

**Open: owner decision (asked 2026-11-27).** A live smoke of the two adapters against
the real providers at the end of the stage: at most 20 calls and 0.50 USD in total,
with the keys already in the environment. Without it the adapters are held only to
recorded and scripted answers, and "works with the real provider" stays unverified
until staging.

## Contract impact

Additive only, as `goOnlyErrors`: `429 AI_QUOTA_EXCEEDED` on
`POST /color-profile/analyze`. Decided per slice if another is needed.

## Testing

Seam: the HTTP handlers over the real router, gate and PostgreSQL; the providers
against a stand-in HTTP server that checks what it is sent; the pure parts (config,
interpretation of model output, context building, colour mathematics) by golden
vectors from the TypeScript code.

- Adapters: the request body for a given input, byte for byte; each status and
  malformed answer to its error kind; timeout and retry.
- Quotas: charge, limit, refund, the day's boundary, concurrency (as `ai-usage.itest`).
- Each pipeline: the scenarios of its Next.js integration test (`wardrobe-vision`
  VIS-01..07, `stylist-chat` STY-01..07, `outfit-intelligence` OUT-01..06,
  `color-profile` COL-01..09, `ai-rollout` ROL-01..02), over HTTP.
- Prompt-injection regressions for the stylist and outfit paths (security checklist).
- e2e: the whole browser suite in Go mode with every operation answered by Go.

## Out of scope

- Background jobs for AI calls (ADR 0011).
- New prompts, models or evaluator rules (owner rule 6).
- Admin views of usage (B8).
