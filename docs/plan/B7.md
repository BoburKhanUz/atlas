# B7 — Cutover: one backend, in Go

Started at `747665d` (2026-11-28). Owner decisions: ADR 0002 (one cutover), ADR 0012
(mobile app only; the website is a landing page), and of 2026-11-28: the user web
pages are kept in Git history, not in the code, so that a Telegram Mini App can start
from them later (the archive point is recorded below when they are removed).

## Problem

Two backends live in the repository: the Go server (B0–B6: every operation of the
contract) and the Next.js API with its server code and Prisma, which nothing in
production ever ran. Every change still has to keep both green (the contract is
generated from the TypeScript registry, Prisma owns the schema, the browser suite
drives the web pages over the Next.js server and the Go server through a test proxy).

## Solution

After B7 the repository has one backend: the Go server owns the API, the contract
document and the database schema; `apps/web` serves only the landing page (at `/`),
the legal pages, the page an e-mailed reset link opens, and later the admin panel,
and calls the Go API for anything it needs.

- **Tests first.** An API journey suite against the Go server (with its worker and a
  real PostgreSQL) takes over what the browser suite proves through the web pages,
  before those pages and the old API go.
- **Schema.** `lookly migrate` applies the Go migrations; on a database Prisma made it
  records the baseline as applied (ADR 0007). Prisma's history is frozen and removed.
- **Contract.** `docs/api/openapi.json` becomes hand-owned (ADR 0003): the TypeScript
  registry and its check go; the Go server and the Dart client are generated from the
  document and CI fails on drift, as today.
- **Evaluation.** The AI evaluation harness keeps its cases, scoring and reports and
  runs the Go pipeline only (`lookly eval`); the TypeScript pipeline it compared
  against goes with the old API.
- **Deployment.** One Compose project: PostgreSQL, the Go server, the Go worker, the
  web app, Caddy (`/api/*` to Go, everything else to the web app, security headers).
- **Staging.** The stack on the owner's VPS, the phone app pointed at it and checked
  by the owner. This last step waits for the VPS and the Cloudflare account.

Nothing has users or data, so there is no data migration and no mixed operation.
